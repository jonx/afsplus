# Open Questions

Decisions that are deliberately unresolved. No agent settles one of them
implicitly by picking the easiest implementation; each is closed by an ADR
that records the decision, after which its row becomes a link to that ADR.
The plan that produces the deciding evidence is [ROADMAP.md](../ROADMAP.md)
Stage B; the review rules are in [AGENTS.md](../AGENTS.md).

| # | Question | Options | What decides it |
|---|---|---|---|
| Q1 | Committed user-data update policy (architecture blocker 1): when an application rewrites an allocated, unshared range, does AFS+ overwrite in place or allocate new blocks until commit? | Full data COW (the executable prototype); in-place overwrite for unshared committed data; a per-file hybrid only if measurements justify its extra semantics. Reflink-shared ranges always COW. | Measured write amplification, fragmentation, crash behaviour before/after metadata commit and content-generation handle cost on random 4 KiB rewrites, VM/database files and reflink-shared writes ([docs/08 § 4](../docs/08-transactions-and-journal.md), [ROADMAP B2](../ROADMAP.md#b2-user-data-update-policy)). |
| Q2 | fsync durability path (blocker 2): does the intent log become an epoch-1 format commitment? | Checkpoint COW with group commit only ([ADR-026](../adr/ADR-026-bounded-atomic-batches.md)); checkpoint COW plus the intent log ([ADR-037](../adr/ADR-037-intent-log.md), experimental). Both are implemented and measured in [fsync-intent-log-baseline.md](fsync-intent-log-baseline.md). | The epoch-1 freeze review of the measured ratios and of the log's crash semantics under identical fault injection. A second complete transaction engine is not built for the comparison ([ROADMAP B3](../ROADMAP.md#b3-checkpoint-and-fsync)). |
| Q3 | Authoritative allocation-state encoding (blocker 3): is the reserved triple-slot bitmap page plus allocation-root pool the frozen encoding? | Reserved-slot bitmap pages with triple-buffered region descriptors and the `3N` allocation-root pool ([ADR-035](../adr/ADR-035-allocation-root-reserved-pool.md), authoritative in the prototype); a delta log; a spacemap/log-structured map. | Stage B1 crash tests and write-amplification measurements at the 1 GiB region size, then the M14 freeze review ([ROADMAP B1](../ROADMAP.md#b1-allocation-state)). |
| Q4 | Retained content generations (blocker 4): how long does an exact older content generation stay readable? | The conservative contract `OpenObjectGeneration(id, generation)` → exact generation if retained, else `GENERATION_NOT_AVAILABLE`; any snapshot-like retention policy beyond it. | Its interaction with Q1 and with reclamation ([ADR-021](../adr/ADR-021-deferred-reclamation.md), [ADR-036](../adr/ADR-036-reclaim-queue.md)), and a real consumer (scanner, backup) that needs stable exact-generation access. |
| Q5 | Rich security semantics (blocker 5): how much cross-platform ACL evaluation does the format define? | A versioned security-descriptor container that preserves unknown metadata across simpler hosts ([ADR-031](../adr/ADR-031-portable-security-acls.md), phase 1); full canonical NFSv4/Windows-like evaluation semantics. | Real POSIX and Windows mapping adapters validating or revising the canonical model ([ROADMAP Stage D](../ROADMAP.md#stage-d-portability-and-host-tooling), [testing/security-model-conformance.md](../testing/security-model-conformance.md)). |
| Q6 | Tiny-file storage ([ADR-018](../adr/ADR-018-inline-data-optional.md) reopened): which mechanism serves source trees and package caches? | Inline data; packed small-file storage; ordinary extents with strong locality. | A measured comparison on Cargo/Git-style trees before epoch 1 ([docs/22](../docs/22-pfs3-and-pfs4-lessons.md)). |
| Q7 | Metadata transaction mechanism freeze ([ADR-009](../adr/ADR-009-journal.md) reopened, [ADR-020](../adr/ADR-020-checkpoint-commit.md) proposed): when is checkpoint COW the frozen epoch-1 mechanism? | Checkpoint COW as executed by the prototype; a conventional redo journal as the comparison candidate. | The checkpoint design passing crash testing and write-amplification benchmarks under fault-injection workloads identical to the journal candidate's ([ADR-009](../adr/ADR-009-journal.md) consequences). |
| Q8 | Which proposed developer primitives stabilise? | Promising and general: stable object IDs, fast full-volume enumeration, persistent change discovery, `CloneFile`/`CloneRange`, bulk metadata operations, explicit durability semantics, explain/health interfaces, access-intent hints. Experimental: `AtomicBatch()`, `SealContent()`, the content-inspection feed, security domains, an online reverse map, recursive directory statistics, a content fingerprint cache, `CloneTree`. | One real application consumer and measured value per primitive; a plausible API is not enough (the Windows TxF lesson). Catalog and change stream are the strongest bets because centralised enumeration and change journals have extensive precedent ([ROADMAP Stage E](../ROADMAP.md#stage-e-developer-contract-accelerators-and-optional-features)). |
| Q9 | Proposals awaiting team review | Tool contract D1–D7, storage media profiles M1–M5, checkpoint slot rings ([proposals/](../proposals/README.md)). | The team's review; on acceptance each lands as an ADR, design document or spec file. |
