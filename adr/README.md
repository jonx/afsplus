# Architecture Decision Records

Decision records are immutable except for their status and relation lines.
Numbers are never reused. The table is generated by
`tools/check-docs.py --write-adr-index`; edit the ADRs, not the table.

Acceptance records a design decision. Implementation and qualification are
tracked separately. Status labels carry no author or approval attribution.
`Partially accepted` on ADR-026 covers internal group commit; its public
AtomicBatch API is proposed. Amendment and supersession links define scope.

## Superseded directions

Directions from the project history that no later ADR supersedes formally.
They are listed so that they are not reactivated by accident; the story of
each is in [NOTES.md](../NOTES.md).

- **Metadata redo journaling as the predetermined transaction mechanism** —
  the initial draft's choice. [ADR-009](ADR-009-journal.md) reopened it after
  the PFS3/PFS4 review; [ADR-063](ADR-063-intent-log-epoch1.md) closes the
  comparison in favor of checkpoint COW plus a bounded intent log.
- **A binary "checkpoint COW versus redo journal" bake-off requiring a second
  complete transaction engine** — replaced by: implement checkpoint COW,
  measure fsync-heavy workloads, add a small intent log only if measurements
  require it ([ADR-037](ADR-037-intent-log.md),
  [ROADMAP B3](../ROADMAP.md#b3-checkpoint-and-fsync)); ADR-063 accepts that
  layered architecture.
- **Exhaustive reachable-state validation at ordinary mount with fallback to
  the older checkpoint** — replaced by bounded structural checkpoint
  selection; full validation belongs to `afsplus-check`, shadow verification
  and the test harness ([docs/08](../docs/08-transactions-and-journal.md)).
- **Bootstrap bump allocation that never reuses blocks** — scaffolding of the
  first prototype, replaced by the region allocator with quarantine
  ([ADR-035](ADR-035-allocation-root-reserved-pool.md),
  [ADR-036](ADR-036-reclaim-queue.md)).
- **One checkpoint record per bitmap page** — replaced by the triple-buffered
  region descriptor selected by one checkpoint record per region
  ([docs/07 § 3.1](../docs/07-allocation.md)).
- **The eager mount walk decoding every object** — replaced by bounded root
  loading with on-demand descendant decoding.
- **Full NFSv4/Windows ACL evaluation semantics in the base writable
  milestone** — deferred to a semantics-later phase by
  [ADR-031](ADR-031-portable-security-acls.md).
- **Inline data as the settled tiny-file mechanism** — reopened by
  [ADR-018](ADR-018-inline-data-optional.md); inline, packed and
  locality-based storage are compared before epoch 1.
